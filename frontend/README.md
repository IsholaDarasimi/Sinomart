# Sinomart Super Store — Frontend

React + Vite + TypeScript + Tailwind v4 + TanStack Query + Supabase JS, built against the
schema in `../database/migrations` and the Edge Functions in `../supabase/functions`.

## Setup

```bash
npm install
cp .env.example .env.local   # fill in your real Supabase project URL/anon key + Paystack public key
npm run dev
```

Requires the database migrations (`../database/migrations/001`–`031`) to already be applied
to your Supabase project, and the Edge Functions (`../supabase/functions/*`) deployed, for
any real data to load — this is a pure client, it has no fallback mock data by design.

## Verified before delivery

- **Types are not hand-written.** `src/types/database.types.ts` was generated by directly
  introspecting a live, migrated, seeded Postgres instance (not guessed from the SQL by
  reading) — see `../database/README.md` for how that instance was built and tested.
- `npx tsc --noEmit -p tsconfig.app.json` passes with **zero errors** across the entire
  ~100-file source tree.
- `npx vite build` succeeds and produces a real production bundle (code-split into
  vendor-react / vendor-query / vendor-charts / vendor-motion / vendor-supabase chunks —
  see `vite.config.ts`).
- Query shapes in `src/services/*` were checked against the real PostgREST embedding syntax
  Supabase uses (e.g. `products(*, product_images(*), product_rating_aggregates(*))`).

**Not yet verified:** full in-browser rendering/interaction (no browser automation was
available in the environment this was built in). The type system, build pipeline, and query
shapes are solid; give the actual click-through UX a pass once you have a real Supabase
project and `npm run dev` running.

## Architecture

- `src/services/*` — the only layer that talks to Supabase (table queries, RPC calls, Edge
  Function calls). Nothing else imports `@/lib/supabase` directly.
- `src/hooks/*` — TanStack Query wrappers around `services/*`, used by pages/components.
- `src/components/ui/*` — hand-written shadcn-style primitives (owned source, not a
  dependency) built on the Radix primitives already in `package.json`.
- `src/context/AuthProvider.tsx` — wraps Supabase Auth (session, profile, role, 2FA-aware
  sign-in flows). `RequireAuth`/`RequireAdmin` in `components/layout/RouteGuards.tsx` gate
  routes — but remember the *real* security boundary is Postgres RLS
  (`../database/migrations/017_rls_policies.sql`), not these client-side checks.
- Money/inventory/checkout never computed client-side: `services/checkout.ts` calls the
  `checkout-start` / `checkout-create-order` Edge Functions, which call the SECURITY DEFINER
  SQL functions in `../database/migrations/015_functions_business_logic.sql`.

## Known gaps / next steps

- Product create/edit form (`pages/admin/AdminProductEditPage.tsx`) covers core fields,
  one image, and a single default purchase option — variants, multiple images, and
  additional purchase options need their own sub-forms following the same pattern.
- Coupon/campaign/banner admin pages are functional CRUD but intentionally lighter than
  Products/Orders/Imports — extend using the same service-layer pattern in
  `src/services/admin/*`.
- No automated test suite (Vitest/Playwright) is included yet.
